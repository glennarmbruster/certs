Exam domain · 20–25%

Tenant and workload configuration

Tenant domain validation

When to use it. A pilot company must use its own verified domain for employee identities before assigning AI licenses.

Adding a custom domain requires proof of DNS ownership in the intended Microsoft 365 tenant. Verify the DNS proof and tenant association before switching production usernames or mail records.

Group-based AI licensing

When to use it. A pilot roster should acquire the same eligible AI service entitlements whenever membership changes.

A group license assignment applies supported products and service plans to qualifying members. Check usage location, seat availability and per-user processing errors before expanding the roster.

Metered billing policy

When to use it. Several departments want supported AI consumption billed to different approved Azure billing scopes.

Pay-as-you-go billing policies connect eligible metered experiences and selected users to a billing arrangement. Verify assigned users and billing scope and reconcile usage with the cost owner's records.

AI service entitlement inventory

When to use it. The CIO asks which users and products are entitled to Copilot, Agent 365 and Copilot Studio capabilities.

Tenant subscriptions, assigned licenses and service plans identify purchased and provisioned entitlements. Check each product's current terms because managing an agent, building it and using a metered action can have distinct entitlements.

Microsoft 365 Backup restore

When to use it. A project site was damaged by an accidental bulk edit and a suitable M365 Backup restore point exists.

The backup workflow restores supported protected workload data using available recovery points. Inspect the selected scope and target restore behavior before running the recovery.

Network connectivity insights

When to use it. Employees at one office report slow Microsoft 365 experiences while other sites are healthy.

Tenant network connectivity insights help identify network egress and connectivity issues by office location. Compare local egress and observed latency with unaffected offices before changing tenant settings.

Service health notifications

When to use it. The service owner wants alerts when a Microsoft 365 service incident affects the pilot tenant.

Service health notification preferences direct relevant incident or advisory updates to administrators. Match the incident's reported impact, workload and timing to the pilot symptoms.

Shared mailbox delegation

When to use it. A project needs a functional mailbox that several employees can read and send from with controlled rights.

Shared mailbox permissions separately govern access to contents and the identity used to send. Validate each delegate's Full Access and sending rights according to their actual role.

Teams meeting Copilot policy

When to use it. After a meeting, users cannot ask Copilot about what was said even though they could use it during the meeting.

Meeting policy and organizer choices govern Copilot availability and whether a transcript supports later use. Verify transcription availability and the meeting's actual settings before investigating license assignment.

SharePoint site permissions

When to use it. The pilot knowledge base needs group-managed reading access and restricted editorial privileges.

SharePoint permission levels and group assignments define what readers and editors can do. Inspect broken inheritance and direct shares that may bypass the intended library-level design.

Restricted Content Discovery

When to use it. A merger project site needs temporary exclusion from broad Copilot discovery while its permissions are reviewed.

A site-level discovery restriction limits supported tenant-wide search and Copilot surfacing. Document a remediation owner and verify direct access separately because discovery suppression does not revoke permissions.

Exam domain · 40–45%

Tenant and workload governance

Graph bulk identity inventory

When to use it. A tenant administrator needs a repeatable inventory of pilot identities and synchronization state.

Graph PowerShell can enumerate user objects with selected properties and pagination. Request nondefault properties explicitly and use -All when the full result set is required.

Guest lifecycle review

When to use it. Partner contracts ended and a site owner suspects external identities retain access to pilot material.

A recurring access review can ask sponsors to decide whether external access should continue. Check the application of review results and direct grants outside the reviewed group.

Administrative unit delegation

When to use it. An operator should manage selected departmental users without receiving tenant-wide directory administration.

Supported Entra roles can be scoped to an administrative unit. Confirm targeted objects are in the unit and that the delegated operation supports scoped administration.

PIM role activation

When to use it. A member of the AI operations team needs temporary elevated administrative authority for an approved release.

Privileged Identity Management activates eligible roles for a bounded period under configured requirements. Check activation status and scope instead of creating a new permanent role assignment.

Authentication method scoping

When to use it. Only a pilot group should initially register a new supported passwordless sign-in method.

Entra authentication methods policies configure permitted methods and target populations. Check effective inclusion and exclusions when a user cannot register the new method.

Entra Password Protection

When to use it. A tenant wants to prevent common weak password patterns and organization-specific banned terms.

Password Protection evaluates password choices against banned-password rules during supported changes and resets. Plan on-premises agents if enforcement must extend to supported on-premises AD password changes.

SSPR writeback verification

When to use it. A hybrid user reset succeeds in the cloud but the new credential does not work on local AD resources.

Password writeback allows supported self-service cloud resets to update on-premises AD. Verify writeback configuration, connector permissions and the source account password policy.

Conditional Access sign-in diagnosis

When to use it. An entitled Copilot pilot user receives an access denial from an unmanaged device.

The sign-in log identifies targeted resources, device signals and policy grant results for the request. Use the actual correlation ID and resource rather than assuming any policy containing the word Copilot caused the block.

Risk-based access remediation

When to use it. A pilot account has a high-risk identity finding and should complete a verified recovery flow.

Identity Protection signals can drive risk-based access controls and supported remediation. Distinguish persistent user risk from one risky sign-in and validate the user can satisfy recovery requirements.

Defender mail incident triage

When to use it. A malicious message sent to pilot users leads to related link clicks and device alerts.

Defender incidents group relevant email and endpoint evidence for coordinated investigation. Check impacted recipients, click activity and post-delivery actions before choosing containment scope.

Safe Attachments policy targeting

When to use it. One business unit receives suspicious attachments despite a custom detonation policy.

Safe Attachments protection depends on the effective policy for the recipient and the configured action. Check applicable preset policies, recipient exclusions and rule priority before modifying the custom rule.

Attack simulation training

When to use it. A security manager wants to measure reporting behavior in an authorized phishing awareness exercise.

A training campaign targets a defined audience and records simulated outcomes and training completion. Review training metrics and target-group exclusions before comparing departments.

Sensitive information type tuning

When to use it. A DLP rule flags random internal reference numbers that resemble a protected identifier.

Sensitive information types can use supporting evidence, proximity and confidence to distinguish meaningful matches. Test realistic positives and near misses before raising thresholds or removing the detector.

Sensitivity label encryption rights

When to use it. Two users see the same labeled file in a library but only one should be able to open and use its contents.

Label encryption can impose usage rights beyond a link or site permission grant. Inspect the actual assigned rights and supported client behavior using representative identities.

Label publishing scope

When to use it. A restricted label was created but pilot editors cannot apply it to documents.

Publishing policies distribute selected sensitivity labels to their intended users and groups. Verify user inclusion, policy propagation and the supported document labeling experience.

Copilot DLP restriction

When to use it. Protected project documents should remain available to authorized people while supported Copilot processing is restricted by policy.

Purview DLP for Copilot can restrict supported processing of matching labeled content in scoped experiences. Inspect the chosen Copilot location, supported condition, action and policy mode before enforcement.

DLP alert investigation

When to use it. An analyst sees a policy alert involving sensitive content and needs to determine whether the activity was blocked.

Alert details identify the matched rule, condition, user, location and configured action. Compare simulation or enforcement mode with the actual action observed for the workload.

Retention label policy

When to use it. A records team needs selected project deliverables kept as records under an item-specific schedule.

Retention labels assign lifecycle behavior to individual supported items and can identify records. Check label application, retention start trigger and disposition configuration together.

DSPM for AI posture review

When to use it. A compliance lead needs a tenant view of AI data-sharing risks and recommended improvements.

Purview AI posture capabilities correlate supported AI activity with data security insights and recommendations. Verify data sources, licensing and observation period before concluding a risk has been remediated.

Site-level access restriction

When to use it. A highly sensitive SharePoint site should admit only users with existing permission who also belong to an approved security group.

Restricted access control adds a membership requirement above ordinary SharePoint permissions. Test that both the group gate and an underlying permission grant are present for an authorized user.

Exam domain · 35–40%

AI services administration

Copilot readiness pilot

When to use it. Before a broad rollout, the organization needs evidence that licenses, clients, work data and access controls support real tasks.

A readiness pilot tests representative personas, applications and data with measurable acceptance checks. Include both an intended-access test and an unexpected-access test before approving expansion.

Oversharing remediation

When to use it. A user can open a confidential spreadsheet directly and Copilot also cites it in an answer.

Removing unintended access at the source corrects the permission path used by the user and supported grounding. Inspect direct grants, group membership, broad sharing links and unique permissions on the specific item.

Web search control

When to use it. Policy should govern whether supported Copilot experiences can use web search as an additional grounding source.

Administrative web search settings control the use of web grounding in supported experiences. Check the tested surface and policy scope because blocking web search does not remove work-content access.

Copilot connector access mapping

When to use it. An external ticket repository is indexed for Copilot Search and one employee sees another department's tickets.

A connector must represent each external item's access control list and map identities correctly. Test external identity mapping using one authorized and one unauthorized user before indexing the full source.

Third-party AI provider governance

When to use it. A team wants to enable an optional AI provider and compliance must assess it before tenant rollout.

Tenant-level provider controls and service terms govern availability of supported external model experiences. Review data handling, region, approved use cases and the settings for the specific provider.

Copilot usage and adoption reports

When to use it. License assignment is complete and leadership asks which workloads actually see active usage.

Usage reports expose engagement for supported Copilot workloads over defined reporting periods. Separate assigned users, active users and specific workload activity when calculating adoption.

AI consumption cost monitoring

When to use it. Sales reports unexpectedly high charges for a metered agent after a new tool was added.

Attributing metered activity to the applicable billing policy and usage driver supports cost investigation. Compare the change window, usage volume, action types and billing scope before adjusting entitlement.

Agent registry discovery

When to use it. An administrator must inventory both Microsoft and third-party agents visible in the tenant.

The registry presents discoverable agents with identity, ownership, publication and management information. Use stable identifiers when two agents have similar names or display branding.

Agent submission review

When to use it. A maker requests publication of an agent that can access customer records and invoke a business action.

Administrative review examines purpose, audience, data sources, tools and permission requests before distribution. Approve only the reviewed scope and record the accountable owner and approval decision.

Agent audience restriction

When to use it. An approved procurement agent should be installed or made available only to the purchasing pilot group.

Agent distribution and access controls determine who can use the published agent in supported surfaces. Validate access with an allowed user and an excluded user and check the underlying data authorizations independently.

Agent owner reassignment

When to use it. The sponsor of a production agent leaves the business during an organizational change.

Ownership governance identifies who remains accountable for an agent's purpose, entitlements and lifecycle. Assign a replacement owner and recertify tool and source permissions before continuing unattended use.

Agent identity lifecycle

When to use it. An agent should have a distinct directory identity that can be provisioned, governed and retired with its operational lifecycle.

Entra Agent ID supports identity governance for supported agent identities and their relationships. Track the agent instance and its associated identity separately from the human maker account.

Agent access package

When to use it. An agent requires a governed set of resources with approval and expiration in a supported entitlement scenario.

An access package bundles resource roles with a policy for granting and expiring the assignment. Scope the package to the intended agent identity and verify effective assignments at expiration.

Conditional Access for agents

When to use it. An organization wants supported agent identities to be evaluated against a policy targeting agent sign-ins.

Agent-targeted Conditional Access applies supported controls to agent identities within scope. Check licensing, supported controls and agent sign-in evidence before enforcing the policy.

Agent tool permission review

When to use it. An information-only agent has been granted a tool able to alter customer records.

Reviewing tool permissions aligns allowed actions and connection identity privileges with the agent's purpose. Remove unnecessary write capability and test the retained read workflow with the actual execution identity.

Agent activity observability

When to use it. A data owner needs to attribute unexpected SharePoint activity to a specific deployed agent.

Supported observability and access reports identify agent activity and the sites or resources involved. Correlate agent identity, timestamp, action and site because the owner identity alone is insufficient evidence.

Agent retirement

When to use it. A discontinued agent must stop serving users and should lose its continuing access to business resources.

A retirement workflow removes distribution and reviews or revokes identity, tool and source access. Check remaining credentials, role grants, connections and metered resources after unpublishing.
