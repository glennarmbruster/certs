Microsoft 365 services and objects

User license assignment

When to use it. A pilot employee can sign in but lacks a paid M365 Copilot experience that other pilot members have.

A qualifying subscription and assigned service entitlement enable licensed experiences for the user. Verify assignment and service-plan provisioning on the actual work account before changing site access.

Microsoft 365 group membership

When to use it. A project participant unexpectedly sees team documents after joining a collaboration group.

Membership can grant access to connected workloads such as the group's SharePoint site. Review group owners, members and guests when evaluating the effective audience of shared content.

SharePoint permission inheritance

When to use it. An analyst should access the project library but not a restricted folder with separate permissions.

Sites, libraries, folders and items can inherit permissions or have unique access lists. Inspect effective access at the exact document because a parent site's membership can be incomplete evidence.

Exchange shared mailbox

When to use it. A department needs a common email address and delegated inbox while individual users retain their own accounts.

A shared mailbox separates a functional mailbox from the employees authorized to open or send from it. Mailbox delegation and a user's Copilot entitlement are separate administrative settings.

Teams private channel

When to use it. Only a subset of a broad project team should collaborate on confidential channel files.

A private channel has its own membership and an associated SharePoint site for channel files. Review the private channel membership and its backing site when investigating access.

Entra single sign-on

When to use it. Staff should authenticate to a trusted identity provider and launch several supported services with one session.

Single sign-on lets applications accept the authenticated session without asking for credentials each time. An existing sign-in does not grant access to a resource whose permissions exclude the user.

Entra Conditional Access

When to use it. Copilot pilot users must meet an organization's device and authentication rules to reach targeted Microsoft 365 services.

Conditional Access evaluates signals at sign-in and enforces scoped grant or session controls. Check the actual target resource and the sign-in policy evaluation for a blocked pilot user.

Privileged Identity Management

When to use it. A user should manage AI settings during an approved change window without holding permanent tenant privileges.

PIM can make a supported administrative role eligible for time-bound activation. Verify activation and the scope of the selected role before attempting the change.

Enterprise applications

When to use it. A tenant administrator needs to inspect the local permissions of a third-party application used in a pilot.

A service principal represents the application in the tenant and holds local grants or assignments. Inspect the tenant-specific enterprise application when reviewing granted access.

Defender XDR incident

When to use it. A reported phishing message and unusual endpoint activity involve the same Copilot pilot employee.

Defender XDR correlates supported security alerts and evidence across workloads for investigation. Review related entities and incident evidence before assuming AI access caused the event.

Organization settings

When to use it. The pilot owner needs to verify tenant-wide service configuration and the company's registered domains.

The Microsoft 365 admin center provides tenant organization settings and domain administration. Confirm the intended tenant before interpreting an organization-wide setting.

Sign-in logs

When to use it. A licensed user reports an authentication error when opening a Copilot experience.

Entra sign-in events identify the targeted resource, authentication details and access policy results. Find the event matching the time and correlation ID before investigating service availability.

Data protection and governance

Permission-trimmed grounding

When to use it. Copilot cites an HR file to a pilot user who can also open it directly. The team needs to explain the exposure.

Work grounding retrieves content within the requesting identity's effective access and applicable controls. Investigate broad sharing links, group memberships and uniquely granted permissions on the source.

Data access governance report

When to use it. The SharePoint owner needs to find sites with evidence of broad sharing before expanding the pilot.

Governance reports surface access and sharing patterns that identify sites needing review. Use the report as a starting point and confirm permissions at the affected site or item.

Site access review

When to use it. An oversharing report identifies a site and the data owner must certify and correct the current audience.

A site owner reviews the people, groups and links that grant access and removes unnecessary grants. Recheck representative users' effective access after remediation.

Restricted Content Discovery

When to use it. A sensitive site needs temporary protection from broad organization-wide search and Copilot discovery during access review.

The setting reduces discovery for the flagged site in supported search and Copilot experiences. A user with permission may still reach content directly, so remediate excessive permissions separately.

Restricted site access control

When to use it. A sensitive SharePoint site should be accessible only to permitted users who are also in a designated allowed group.

Restricted access control adds a group membership boundary to existing SharePoint permissions. Membership in an allowed group by itself does not grant SharePoint access to the site.

Sensitivity label encryption

When to use it. A confidential document must carry enforceable usage rights when it leaves its original library.

A sensitivity label configured with encryption can specify who may open and use supported content. A label with only visual markings does not enforce the same rights as encryption.

Sensitivity label publishing

When to use it. Pilot users cannot choose a newly created classification label in supported Office applications.

A label publishing policy makes selected labels available to users and groups. Verify both the included label and the target audience before troubleshooting the client.

Purview DLP alert

When to use it. Compliance needs to review a policy match involving sensitive information in a supported workload.

DLP alerts identify the policy, rule, matched conditions and relevant activity for investigation. Inspect location, rule mode and exceptions before treating an alert as proof that an action was blocked.

DSPM for AI

When to use it. A compliance lead wants visibility into AI interactions and data risks across supported AI experiences.

Data Security Posture Management for AI surfaces AI activity, risk insights and posture recommendations. Verify enabled data sources and role permissions before interpreting an empty dashboard.

Retention of Copilot interactions

When to use it. The organization must retain supported Copilot prompts and responses for a defined period.

Purview retention policies can govern supported AI interaction content through the relevant locations. Verify the selected AI interaction location and licensed capabilities when testing preservation.

Communication Compliance

When to use it. A compliance team needs supervised review of policy-flagged communications in supported channels.

Communication Compliance applies scoped policies and routes matching communications into a reviewer workflow. Limit reviewer privileges and evaluate the actual communication in context.

Insider Risk Management

When to use it. Compliance wants to correlate permitted risk indicators across activities when investigating potential insider data misuse.

Insider Risk Management uses configured indicators and policies to surface potential risk for authorized analysts. Apply privacy controls and investigate evidence before drawing conclusions about an individual.

Purview eDiscovery

When to use it. A legal team needs to find preserved AI interactions and related documents for a named matter.

eDiscovery searches supported content locations under case-based permissions and workflows. Check the custodians, workload support, query conditions and preservation status for the case.

Copilot and agent administration

Copilot readiness assessment

When to use it. A business unit wants to know which users can start a licensed pilot and what prerequisites remain.

Readiness checks cover eligible licensing, supported applications, identity and accessible work data. Validate the actual in-app experience with representative users before expanding rollout.

Pay-as-you-go billing policy

When to use it. A department wants supported metered AI usage allocated to a specific Azure subscription.

A billing policy links eligible consumption scenarios to a billing scope and selected users or groups. Confirm metering eligibility and monitor actual usage and cost after enabling the policy.

Copilot usage reporting

When to use it. An adoption lead needs to see whether assigned pilot users actually engage with Copilot in each supported workload.

Usage reports summarize active users and activity over reporting windows. Distinguish assigned licenses from active use and account for reporting latency.

Researcher agent

When to use it. A manager needs a sourced synthesis spanning several permitted materials for a strategic review.

Researcher performs multistep research and assembles a cited report from available sources. Open the cited sources to verify that they support the report's conclusions.

Analyst agent

When to use it. A team needs to examine a tabular dataset and discover trends or anomalies using a dedicated analysis experience.

Analyst supports data exploration and structured analysis using supplied or accessible data. Reconcile totals and assumptions against the source dataset before publishing findings.

Custom agent instructions

When to use it. An internal assistant should consistently answer a narrow business process question using approved guidance.

Agent instructions specify the intended role, behavior and boundaries of a task-focused agent. Test ambiguous and out-of-scope requests as well as a normal success case.

Agent publication approval

When to use it. A maker wants an internally built agent distributed more broadly and an administrator must approve its release.

An approval workflow lets administrators evaluate a submitted agent before making it available to its intended users. Review the owner, knowledge sources, permissions and requested actions before publishing.

Agent registry

When to use it. The tenant needs an inventory of discovered agents, their ownership and administrative status.

The registry provides a central view for discovering and managing supported agents. Confirm the specific agent ID and publisher when similarly named agents appear.

Agent audience assignment

When to use it. An approved agent for the legal pilot should be available only to a designated test group.

Distribution and access settings target the users who can discover or use the agent in supported experiences. Test with an included user and an excluded user because agent availability and source permissions are distinct.

Agent lifecycle owner

When to use it. A production agent's maker leaves the company and the team needs continued oversight of its data and actions.

A designated accountable owner can review purpose, access and ongoing operation through the agent lifecycle. Reassign ownership or retire the agent and review residual access before the old owner is removed.

Agent usage monitoring

When to use it. A published pilot agent receives unexpected traffic and the service owner needs to understand adoption and operational behavior.

Agent analytics and administrative monitoring show supported usage and operational signals. Compare usage against intended audience and investigate scope or billing changes before broadening access.
