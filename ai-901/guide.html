AI concepts and capabilities

Fairness evaluation

When to use it. A model's overall accuracy looks acceptable but performance may vary across demographic groups.

Disaggregated evaluation compares error patterns across relevant groups to reveal disparities hidden by the average. Use representative samples and examine meaningful error measures for the actual decision context.

Reliability and safety testing

When to use it. A service must behave predictably when input is noisy, incomplete or outside its normal range.

Stress testing and failure handling assess the system under expected and adverse conditions. Define a safe fallback when confidence is insufficient or a tool dependency fails.

Privacy and security

When to use it. A prototype works with personal information and must limit who can access its prompts, outputs and logs.

Data minimization, access controls and protected storage reduce exposure throughout the AI lifecycle. Review logging and retention because sensitive values can appear outside the original source system.

Inclusive design

When to use it. A voice-based assistant should work for people who cannot hear or speak easily.

Alternative input and output modes and accessible interactions broaden who can use the system. Test with representative users and assistive technologies rather than relying only on automated checks.

Transparency

When to use it. Users need to understand the role of AI, its limitations and the evidence behind a generated answer.

Clear disclosures, source references and explanations help people interpret system behavior. Explain uncertainty and material constraints in language the intended audience can understand.

Accountability

When to use it. A production model generates a harmful recommendation and the team needs an escalation and correction path.

Named owners and documented decision procedures keep people responsible for oversight and remediation. Define who can stop the system, review incidents and approve changes before deployment.

Token-based generation

When to use it. A fluent model answer includes a plausible but unsupported fact.

A language model predicts tokens from learned patterns and context, which can produce convincing errors. Verify factual claims using authoritative evidence even when the wording sounds confident.

Model capability selection

When to use it. An application must interpret a diagram and answer a natural-language question about it.

A multimodal model with image understanding can accept both visual and textual input. Check the specific deployment's supported modalities and limits before designing the client.

Sentiment analysis

When to use it. A customer experience team wants positive, neutral or negative signals from support comments.

Sentiment analysis classifies expressed attitude in text at supported levels of granularity. Check sarcasm, language and mixed statements when evaluating classification accuracy.

Named entity recognition

When to use it. A reviewer needs to identify organizations, locations and people mentioned in unstructured text.

Entity recognition identifies text spans and assigns supported entity categories. Validate ambiguous names in context and check supported language capabilities.

Key phrase extraction

When to use it. A survey analyst needs short phrases capturing prominent topics from many comments.

Key phrase extraction identifies salient terms or phrases from the supplied text. Review phrases in context because frequency or salience does not establish business importance.

Speech recognition

When to use it. Recorded customer interviews must be converted into text for later analysis.

Speech-to-text transcribes spoken audio into written language. Evaluate recognition with representative accents, background noise and domain terminology.

Speech synthesis

When to use it. A text-based notification should be available as spoken audio.

Text-to-speech renders supplied text through a selected synthetic voice. Check pronunciation and locale for abbreviations, names and specialized vocabulary.

Image classification

When to use it. A production-line image must be assigned one label representing its overall category.

Image classification predicts one or more labels for the whole image. Use object localization when the application also needs individual object coordinates.

Optical character recognition

When to use it. A photographed sign must be converted into visible characters for a search index.

OCR extracts text from visual input and may return location information. Evaluate small fonts, skew and low contrast because the visible content can be difficult to recognize.

AI solutions with Microsoft Foundry

Foundry project

When to use it. A development team needs a shared workspace for model deployments, agents and project connections.

A Foundry project organizes supported AI development resources and access for a workload. Confirm project identity and assigned roles when a team member cannot see expected assets.

Model catalog

When to use it. A team must shortlist candidate models for language coverage, image input and latency before deployment.

The catalog exposes model capabilities and deployment options for evaluation. Compare model cards, supported modalities and deployment regions with application requirements.

Model deployment name

When to use it. A client can authenticate but its inference request references a model name never deployed under that name.

An inference request must identify a valid deployment for the configured endpoint and API. Match the deployment identifier exactly with the name configured in the target Foundry resource.

System instructions

When to use it. A service must consistently return concise answers, cite supplied material and acknowledge missing evidence.

System-level instructions describe stable behavior and constraints for the model interaction. Keep sensitive credentials out of prompts and enforce authorization in the application layer.

User prompt design

When to use it. A chat client needs an answer for one specific task with a defined audience, source and requested format.

The user message supplies the current task and task-specific inputs within the application's instruction context. Use clearly delimited source material and explicit output requirements for the current turn.

Temperature configuration

When to use it. A supported text-generation deployment needs less variation for repeated structured drafting tasks.

A lower temperature generally concentrates token sampling on higher-probability choices. Lowering temperature does not guarantee deterministic or factually correct output.

Output token limit

When to use it. A generated answer regularly stops in the middle of its final section due to a response length cap.

The configured maximum output token count limits how much text the model can generate. Inspect the finish reason and account for the total context budget before increasing the limit.

Foundry playground

When to use it. A developer wants to compare prompt behavior interactively against an existing deployment before writing a client.

A playground provides an interactive interface for testing supported model inputs and settings. Record the deployment, instructions and parameter values for a repeatable comparison.

SDK client authentication

When to use it. A lightweight application must call a Foundry project endpoint using its own managed workload identity.

A supported SDK client can use an Entra credential with a correctly scoped data-plane role. Confirm endpoint, tenant, identity and role assignment separately when authentication succeeds but authorization fails.

Retrieval-augmented generation

When to use it. A product assistant needs answers grounded in a frequently updated manual without retraining model weights.

Retrieval selects relevant source passages and includes them as context for answer generation. Check retrieval quality and document access permissions before attributing wrong answers to the generator.

Agent tool configuration

When to use it. A single agent should retrieve shipment status from an approved business service.

A tool definition and its execution path let the agent request a bounded external capability. Validate arguments and authorize the action in the execution layer before returning a tool result.

Agent conversation state

When to use it. A support agent must refer to an order already identified in earlier turns of the same conversation.

Conversation state links relevant messages and tool results across a multistep interaction. Isolate conversations by authorized user or session to avoid cross-customer context leakage.

Agent evaluation set

When to use it. A prototype agent must be tested for correct answers, appropriate tool use and safe fallback behavior.

A fixed set of representative cases allows comparison of behavior across versions and configurations. Include missing data, denied access and tool failures along with straightforward requests.

Text analysis client

When to use it. An application must call a language analysis capability for many short documents and attribute results correctly.

A text analysis client submits documents and returns supported per-document results and errors. Match results by document ID and inspect partial failures before aggregating the output.

Speech recognition client configuration

When to use it. An application sends audio to Azure Speech but receives no useful transcript although recordings play locally.

Client-side speech setup must select the supported input stream, encoding and recognition language. Check cancellation details, audio configuration and region or endpoint before changing the model.

Multimodal audio interaction

When to use it. A conversational experience must accept spoken input and produce an appropriate supported audio or text response.

An audio-capable deployed model can process supported audio inputs within a multimodal interaction. Validate the model's supported audio format and output mode in the selected API.

Visual prompt construction

When to use it. A user wants a model to interpret a chart rather than invent an illustration of it.

A vision-capable model receives the image alongside an instruction about the content to inspect. Provide readable axes and ask for uncertainty when small labels cannot be distinguished.

Image generation deployment

When to use it. A designer needs a new illustration based on text describing style, layout and subject.

An image-generation model produces a new visual output from supported text or image instructions. Check generated text and details visually before using the asset in a published report.

Document extraction schema

When to use it. A workflow must capture invoice number, total and line items as typed fields instead of a plain transcript.

A Content Understanding analyzer can extract structured fields defined by an appropriate schema. Validate totals, field types and low-confidence or missing fields before posting extracted data.

Audio and video analysis

When to use it. An operations team needs structured insights from recorded calls and training videos using a common extraction workflow.

Content Understanding supports analyzers for modalities including audio and video with configurable output fields. Choose an analyzer and segmentation approach that fit the media type and information required.

Asynchronous analysis polling

When to use it. A client submits a long document and receives an operation reference instead of finished extraction results.

Long-running analysis returns an operation that the client polls until the service reports a terminal state. Handle failed and incomplete results explicitly before reading fields from a completed response.
