Azure identities and governance

Management group assignment

When to use it. A policy must apply to every subscription in a finance hierarchy, including subscriptions added later.

Assigning policy to the common management group allows inheritance by descendant subscriptions. Confirm that a newly added subscription actually sits under the intended management group.

Resource-group role assignment

When to use it. An operator may manage virtual machines in one project group without receiving subscription-wide rights.

Assigning a VM management role at resource-group scope limits the scope of its allowed actions. Check whether inherited roles from higher scopes already grant additional access.

Role definition inspection

When to use it. A reviewer needs to see the allowed management actions and data actions in a custom Azure role.

A role definition describes permissions independently of the principal and scope used by an assignment. Inspect Actions and DataActions separately when the same resource exposes a management and data plane.

Group-based license assignment

When to use it. New employees should receive a licensed service whenever they join an eligible group.

License assignments on a group are processed for qualifying members. Check usage location and assignment errors when one member lacks the expected service plan.

Guest invitation

When to use it. A contractor from a different organization needs a guest identity to receive a project role.

B2B invitation provisions a representation of the external user in the resource tenant. Verify the invitee redeemed the invitation using the intended home identity.

Azure Policy remediation task

When to use it. An existing fleet already violates a modify policy that adds cost-center tags.

A remediation task applies the supported corrective action to existing noncompliant resources. Grant the policy assignment's managed identity the roles required for remediation.

CanNotDelete lock

When to use it. The team must prevent control-plane deletion while allowing configuration changes.

A delete lock allows authorized modifications but blocks deletion of the protected resource. Inspect parent scopes for inherited locks when a deletion request fails.

Budget threshold alert

When to use it. A subscription owner wants notification when forecast spend crosses the monthly allocation.

A budget compares actual or forecast charges to a configured threshold and notifies recipients. Confirm budget scope and notification settings because a budget does not automatically cap spend.

Tag-based cost grouping

When to use it. A business owner wants cost analysis grouped by environment across multiple project groups.

A consistent environment tag enables supported charges to be filtered and grouped. Check for untagged resources and differences in tag application dates when totals appear incomplete.

Administrative unit

When to use it. Help desk staff should administer selected directory users in a region without tenant-wide scope.

A supported directory role can be assigned within an administrative unit. Confirm object membership and whether the delegated role supports administrative-unit scope.

Self-service password reset registration

When to use it. A scoped employee cannot use the self-service reset flow despite being licensed.

The user needs permitted registered authentication methods that satisfy the reset policy. Check the number and types of methods registered against the configured requirement.

Exam domain · 15–20%

Storage

User delegation SAS

When to use it. A team needs a limited blob access URL signed using Entra credentials instead of the storage account key.

A user delegation key signs a SAS with specified permissions and validity dates. Use the shortest practical expiry and give the signing principal only the required rights.

Stored access policy

When to use it. An existing service SAS for a container must be governed by a server-side expiry policy.

A named stored access policy can control supported service SAS permissions and time bounds. Verify the SAS references the policy identifier because an ad hoc SAS is independent of it.

Zone-redundant storage

When to use it. A storage workload must remain available after a zone failure while maintaining synchronous copies in its region.

ZRS synchronously replicates data across separate availability zones in the primary region. Validate regional and storage account support before selecting this replication option.

Blob lifecycle management

When to use it. Block blobs should move to a cooler supported tier after a specified age without a recurring script.

Lifecycle rules evaluate filters and time conditions to perform tiering or deletion. Allow for asynchronous evaluation and check matching prefixes and blob types.

Blob versioning

When to use it. An operator needs earlier versions of a supported blob after repeated overwrites.

Enabling versioning preserves prior versions and assigns each a version identifier. Account for storage costs from retained versions and plan lifecycle cleanup.

Blob soft delete

When to use it. A recently deleted blob needs to be recoverable during a configured retention window.

Soft delete keeps deleted blob data recoverable for the defined retention interval. Issue an undelete before the retention interval expires and check versioning interactions.

Azure Files share snapshot

When to use it. An administrator needs a read-only point-in-time view of files within an existing Azure file share.

Share snapshots capture a differential point-in-time representation of share data. Restore the required file or directory from the selected snapshot and verify its timestamp.

AzCopy

When to use it. An operator must script a high-volume transfer of blobs between supported storage locations.

AzCopy performs command-line data transfer with job tracking and parallelism. Use azcopy jobs show for the transfer job and check failures rather than assuming every object copied.

Storage firewall virtual network rule

When to use it. A storage account's public endpoint should accept traffic from an approved service-endpoint-enabled subnet.

A network rule allows a selected subnet identity to reach the storage account endpoint. The caller must still present valid data-plane authorization after network admission.

Exam domain · 20–25%

Compute resources

Bicep deployment

When to use it. Infrastructure engineers want concise declarative source that deploys through Resource Manager.

Bicep compiles to an ARM JSON template and uses Azure's native deployment engine. Use parameters for environment differences and review the planned scope before applying changes.

ARM what-if

When to use it. An operator must preview resource changes from a template before deployment.

What-if evaluates a proposed deployment and reports expected creates, updates and deletions. Review limitations and provider-computed properties when interpreting the proposed differences.

Availability set

When to use it. VMs in one region must be spread over underlying fault and update domains as a group.

An availability set distributes its VMs across hardware and planned-maintenance boundaries. Place multiple application instances in the set because one VM alone cannot provide instance redundancy.

Virtual Machine Scale Sets

When to use it. A stateless API needs an elastic group of similarly configured VM instances.

A scale set manages a collection of VMs with coordinated configuration and scaling. Validate instance health and deployment policy before rolling a new model through the fleet.

VM resize

When to use it. A workload needs a larger memory allocation per virtual machine while keeping the existing VM resource.

Resizing changes the VM SKU and available CPU, memory and device limits. Check size availability, disk support and restart or deallocation requirements first.

Managed data disk

When to use it. A VM needs persistent application storage independent of its temporary disk.

A managed disk is a separate Azure storage resource attached to a compatible VM. Initialize and mount the newly attached disk inside the guest operating system.

Azure Container Registry

When to use it. A deployment needs a private location to publish and retrieve versioned container images.

Container Registry stores images and artifacts in repositories referenced by tag or digest. Grant the runtime an appropriate repository pull permission before troubleshooting the image itself.

Azure Container Instances

When to use it. A team needs to execute a small container group without managing a cluster or VM hosts.

ACI starts containers as a managed group with supplied image, CPU and memory specifications. Inspect group events and container logs if an image pull or startup fails.

Azure Container Apps revision

When to use it. A containerized API needs two application versions live with controlled HTTP traffic splitting.

Container Apps revisions represent versioned application configurations that can share ingress traffic. Use multiple-revision mode and validate traffic weights when testing a staged rollout.

App Service deployment slot

When to use it. A web team wants to warm a staging deployment and then move it into production with a swap.

Slots provide separate live app deployments that can swap application content and supported settings. Mark environment-specific configuration as slot settings before swapping.

App Service plan scale-out

When to use it. Several applications on a plan face more requests and need additional worker instances.

Scaling out adds instances to the App Service plan that runs the applications. Check how other apps on the same plan share the resulting compute capacity.

App Service custom domain binding

When to use it. A public web app should serve a verified company hostname over HTTPS.

A domain binding associates the verified hostname with the app and a TLS binding presents its certificate. Check DNS verification records, certificate coverage and the hostname binding together.

Exam domain · 15–20%

Virtual networking

VNet peering

When to use it. Two Azure networks with nonoverlapping address ranges require direct private connectivity.

Peering connects virtual networks using the Microsoft backbone. Peering is nontransitive, so a third network requires its own connectivity design.

User-defined route

When to use it. Traffic for a destination prefix must traverse a network virtual appliance before leaving a subnet.

A route table can override the default next hop for matching destination prefixes. Associate the route table with the source subnet and inspect effective routes on its NIC.

Effective security rules

When to use it. Several subnet and NIC policies exist and an administrator needs their combined NSG filtering view.

The effective rules view aggregates applicable network security group rules for a network interface. Inbound traffic must pass both applicable subnet and NIC filtering.

Application security group

When to use it. Security policy should identify application tiers without rewriting rules for every new VM address.

NSG rules can reference logical groups of network interfaces representing application roles. Ensure the relevant network interface IP configurations belong to the intended group.

Azure Bastion

When to use it. Administrators need browser-based management connections to private VMs without public IPs on those VMs.

Bastion brokers RDP or SSH access into a virtual network. Check connectivity from the Bastion subnet to the target management port.

Service endpoint

When to use it. A subnet needs to identify itself to a supported Azure service while reaching the service's public endpoint.

A service endpoint extends virtual network identity to a supported service over an optimized route. Configure the service-side virtual network rule as well as the subnet endpoint.

Private DNS zone link

When to use it. A VM in a spoke cannot resolve records in a separately created Azure private DNS zone.

Linking the zone to a virtual network makes its records available to supported Azure DNS clients there. Check the VNet link and any custom DNS forwarding path when a private record returns no answer.

Internal load balancer

When to use it. A private application tier needs a layer-four frontend reachable only within connected networks.

An internal load balancer distributes connections from a private frontend address to healthy backend instances. Match the frontend rule, backend pool and health probe to the actual listener.

Network Watcher next hop

When to use it. A VM sends traffic to the wrong appliance and the team needs the selected route for one destination.

Next hop reports the next-hop type and address Azure selects for a VM's traffic to a destination. Compare the result with effective routes and the longest matching prefix.

Exam domain · 10–15%

Monitoring and maintenance

Diagnostic setting

When to use it. A resource's platform logs must flow to a Log Analytics workspace for later correlation.

A diagnostic setting routes selected categories to one or more supported destinations. Enable the required categories at the source before querying for previously uncollected events.

Metric alert

When to use it. Average CPU on a production VM must trigger a notification when it stays high for a defined window.

A metric alert evaluates a time-series aggregation against a threshold. Choose the evaluation frequency and aggregation window to avoid confusing a single peak with sustained pressure.

Action group

When to use it. Several alerts should invoke the same approved notification recipients and automation actions.

An action group packages notification and automated response endpoints for reuse. Test the action group independently when alert instances fire but operators receive no notification.

Azure Activity Log

When to use it. An operator needs to determine who changed an Azure resource's control-plane configuration.

The Activity Log records subscription-level management events and their callers. Filter by resource, operation and correlation ID when tracing a failed deployment.

Connection Monitor

When to use it. A network team wants continuous reachability and latency observations between defined endpoints.

Connection Monitor runs configured recurring connectivity tests and reports results. Verify agents or endpoint prerequisites on the selected sources.

Azure Backup recovery point

When to use it. A file server must recover from accidental deletion using a copy captured before the incident.

A recovery point provides restorable data from a protected workload at a particular time. Choose a recovery point older than the deletion and test the restored data.

Azure Site Recovery test failover

When to use it. A company needs a nondisruptive rehearsal of its replicated VM recovery plan.

Test failover creates test instances from replicated data without interrupting production replication. Use an isolated test network and clean up the test after validating recovery.
