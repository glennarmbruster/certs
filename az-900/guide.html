Cloud concepts

Public cloud

When to use it. A startup wants to rent capacity from a provider that also serves unrelated customers.

The provider operates shared infrastructure and offers isolated resources to many customers. A dedicated subscription provides a management boundary while the provider retains the physical estate.

Private cloud

When to use it. A manufacturer needs cloud-style self-service on infrastructure reserved exclusively for its organization.

A single organization has exclusive use of the underlying cloud environment. The organization must arrange capacity and operations itself or contract someone to do so.

Hybrid cloud

When to use it. A retailer must keep its factory system locally and extend its application into Azure.

Connected private and public environments let parts of one workload run in both places. Plan connectivity and identity across the two environments before moving a dependent component.

Consumption-based pricing

When to use it. A seasonal job should incur compute charges in proportion to what it uses.

Metered units convert actual resource consumption into operating expense. Check the billing meter for each service because allocated disks can continue generating charges after compute stops.

Elasticity

When to use it. An ordering service needs extra instances at lunch and fewer immediately after the rush.

Capacity expands and contracts as demand changes. Choose a scale-in rule as well as a scale-out rule to release excess instances.

High availability

When to use it. A short hardware outage must cause as little interruption to a customer-facing service as possible.

Redundant serving components keep requests flowing when an individual component fails. Test failover with an instance unavailable and observe whether traffic reaches healthy capacity.

Disaster recovery

When to use it. A company needs to resume service in another location after losing its primary region.

Recovery procedures restore or fail over the workload to an alternate environment. Set recovery time and recovery point objectives and exercise the recovery plan.

Infrastructure as a service

When to use it. A vendor application requires administrators to install a specific kernel driver inside its server.

The customer manages the guest operating system and application on provider-hosted compute. Budget for guest patching and application backups even though the provider maintains the host.

Platform as a service

When to use it. Developers want to deploy their application code while a provider maintains the operating system and runtime.

A managed application platform abstracts guest operating system maintenance. Check the supported runtimes and versions before committing the application to the platform.

Software as a service

When to use it. Employees need a finished email service without operating mailbox servers or deploying application code.

The vendor operates the complete application and delivers it to subscribers. The customer still assigns access and configures how its users handle organizational data.

Vertical scaling

When to use it. A single-node database needs more memory per running server and cannot partition its workload.

Resizing the existing instance changes its CPU or memory capacity. Check the target size and interruption requirements because resizing can restart the instance.

Horizontal scaling

When to use it. A web tier can distribute requests and needs to grow beyond the size of one server.

Multiple instances share the workload behind a traffic distribution mechanism. Externalize session state or account for session affinity before adding interchangeable workers.

Shared responsibility model

When to use it. A team moving to the cloud needs to assign ownership of physical security, guest patches and identities.

Responsibility for each layer depends on the service model and the component being protected. Map duties individually because using a managed service still leaves the customer responsible for its data and access.

Azure architecture and services

Azure region

When to use it. A data residency review asks where the selected Azure deployment area is physically located.

A region is a geographic area containing datacenters connected through a low-latency network. Check the particular service's availability and data residency commitments in the chosen area.

Availability zones

When to use it. A production service must tolerate failure of a datacenter within the same supported region.

Separate physical zones have independent power, cooling and networking. Use a zone-redundant service or deliberately distribute zonal resources across multiple zones.

Resource group

When to use it. An application and its dependent resources should be administered and retired as one lifecycle unit.

A resource group is a logical container for resources inside one subscription. Deleting the group also deletes resources it contains, including resources deployed in other regions.

Subscription

When to use it. Finance wants a distinct billing and administration boundary for a new internal division.

A subscription provides a boundary for resource usage, quotas and access assignments. Associate the subscription with the appropriate billing arrangement and Entra tenant.

Management group

When to use it. One governance rule must flow down to multiple Azure subscriptions.

Management groups arrange subscriptions hierarchically so policy and access assignments can inherit. Choose a parent that includes every intended subscription and review the effect on descendants.

Azure Virtual Machines

When to use it. A legacy installer requires local administrator access to an entire Windows server.

A virtual machine exposes a guest operating system on configurable compute and disks. Select a compatible image and size and arrange guest updates and monitoring.

Azure Functions

When to use it. A short piece of code should execute when a supported event arrives in a queue.

A trigger invokes a function and bindings can connect input and output services. Match the hosting plan to the execution duration, networking and scale requirements.

Azure App Service

When to use it. A web team needs a managed host for an HTTP application with deployment slots on a supported tier.

App Service runs web applications and APIs on an App Service plan. Scale and feature availability depend on the plan that hosts the application.

Azure Virtual Desktop

When to use it. Remote staff need a centrally hosted Windows desktop with pooled sessions.

Session hosts in a host pool deliver desktops or applications to assigned users. Configure user assignments and ensure session hosts can reach their required services.

Azure Virtual Network

When to use it. An application requires a private Azure address space split into frontend and database subnets.

A virtual network provides logically isolated IP networking for Azure resources. Plan address ranges to avoid overlap with other networks that may later connect.

VPN Gateway

When to use it. A branch office needs an encrypted site-to-site connection across the public internet.

A virtual network gateway terminates IPsec/IKE tunnels to a compatible on-premises device. Verify shared settings, routes and address prefixes on both ends of the tunnel.

ExpressRoute

When to use it. A datacenter wants provider-provisioned private connectivity into Microsoft cloud services.

An ExpressRoute circuit carries private connectivity through a connectivity provider. Private transport alone does not guarantee end-to-end encryption of application data.

Blob Storage

When to use it. A service must store millions of photos and retrieve them as objects by name.

Blob containers organize unstructured objects accessed through storage APIs. Choose an access tier according to retrieval frequency, latency and retention costs.

Azure Files

When to use it. A legacy application requires a managed network file share mounted by multiple clients.

Azure Files exposes managed file shares through supported file protocols. Verify protocol, networking and identity support before mapping the share.

Azure Queue Storage

When to use it. A producer and background worker need an inexpensive backlog of asynchronous work messages.

A queue buffers messages until workers retrieve and process them. Design processing to tolerate redelivery when a worker fails before deleting a message.

Microsoft Entra ID

When to use it. A cloud application needs a directory that authenticates employees and issues access tokens.

The tenant identity service manages users, groups, applications and sign-in. Check the tenant and application registration when a user signs in against an unexpected directory.

Azure role-based access control

When to use it. A developer needs permission to operate a resource group but should receive no rights in sibling groups.

A role assignment connects a security principal, a role definition and a resource scope. Review inherited assignments as well as direct assignments when evaluating effective access.

Azure DNS

When to use it. A team needs an authoritative host for the public DNS records of its application domain.

A DNS zone holds resource record sets that authoritative servers answer for the domain. Delegate the domain at the registrar to the name servers assigned to the zone.

Private endpoint

When to use it. A storage service must be reachable through a private IP address inside a virtual network.

A network interface maps a private address to a supported service through Private Link. Verify name resolution points clients to the private address and configure public access separately.

Azure management and governance

Azure Policy

When to use it. New resources deployed outside approved regions must be rejected automatically.

A policy definition evaluates resource properties and an assignment applies an effect such as deny. Check assignment scope and exemptions when a supposedly blocked deployment succeeds.

Resource lock

When to use it. A production database must resist accidental control-plane deletion even by an authorized operator.

A CanNotDelete lock blocks control-plane deletion while allowing permitted changes. Inspect inherited locks on the parent group when a resource deletion fails.

Tags

When to use it. Finance wants searchable cost-center labels attached to resources without changing permissions.

Tags are name-value metadata used for organization and supported cost reporting. Resource tags do not automatically inherit from a resource group without an additional mechanism.

Pricing calculator

When to use it. Architects need a predeployment estimate for a proposed Azure configuration.

The calculator models anticipated charges from selected products, regions, tiers and usage. Treat the estimate as an assumption-based forecast and revisit it when usage changes.

Cost analysis

When to use it. An owner needs to identify which deployed service caused last month's spending increase.

Cost analysis groups and filters recorded cost and usage within a billing scope. Choose the relevant date range and group by service or resource before drilling into spikes.

Azure budget

When to use it. An owner wants an email when actual or forecast monthly spending reaches a target.

Budget thresholds trigger notifications against monitored spending. A budget notification alone does not stop resources from consuming billable services.

Azure Advisor

When to use it. An administrator wants recommendations for underused resources and other architecture improvements.

Advisor analyzes configuration and usage signals and proposes improvements. Review the effect on workload performance before acting on a right-sizing recommendation.

Azure Service Health

When to use it. An administrator needs information about a Microsoft incident affecting subscribed services in a region.

Service Health provides a personalized view of service incidents and planned maintenance. Configure alerts for the subscriptions, regions and services the team operates.

Azure Resource Health

When to use it. A user asks whether one specific virtual machine is unavailable due to an Azure platform issue.

Resource Health reports the availability status of a supported individual resource. Review the asset's availability history alongside its workload telemetry.

Azure Monitor metrics

When to use it. An operator needs a time series of platform CPU values aggregated into one-minute intervals.

Numeric measurements are stored against timestamps and dimensions for charting and alerts. Choose an appropriate aggregation because an average can hide short peaks.

Log Analytics

When to use it. An investigator needs to correlate records from different tables using a query language.

A workspace stores log data that can be explored with Kusto Query Language. Confirm that the relevant diagnostic data arrived in the queried workspace and time window.

Application Insights

When to use it. Developers need end-to-end request, dependency and exception telemetry for an application.

Application instrumentation records traces and performance data for individual operations. Correlate a failed request with its dependency calls using the operation context.

Azure Resource Manager templates

When to use it. A team wants to express a repeatable deployment in declarative JSON.

A template describes the desired resources and properties for Resource Manager to deploy. Parameterize environment-specific values instead of copying separate templates per environment.

Azure Arc

When to use it. A governance team needs an Azure management view of supported servers running outside Azure.

Arc projects external resources into Azure so supported management capabilities can be attached. Onboard the server and check its connection status before expecting management data.

Azure Cloud Shell

When to use it. A user with only a browser needs an authenticated command-line environment to manage Azure.

Cloud Shell provides hosted Bash or PowerShell with Azure administration tools. Select the intended subscription context before running commands against resources.

Microsoft Purview data catalog

When to use it. Data stewards want to discover and classify sources across the organization's data estate.

Catalog and scanning capabilities describe data assets and their metadata for discovery. Register supported sources and grant scanning access before expecting assets in the catalog.
