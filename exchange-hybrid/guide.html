Mail flow and connectors

Get-MessageTraceV2

When to use it. A sender reports an NDR and supplies the recipient and UTC time. You need the Exchange Online transport record for that delivery attempt.

The trace query locates message-level results within the requested sender, recipient and time bounds. Use windows of up to ten days within the available 90-day trace history and handle result limits.

Get-MessageTraceDetailV2

When to use it. A summary shows different outcomes for two recipients of the same message. You need events for the affected delivery branch.

Trace detail follows events for a selected message trace ID and recipient address. Use the exact recipient from the matching trace row to avoid investigating a different branch.

Internal relay accepted domain

When to use it. During coexistence, some valid addresses in a shared SMTP namespace are hosted downstream and are unknown locally.

An internal relay domain allows recipients outside the local directory to be routed to another mail system. Provide a working downstream route and test unknown recipients for loops.

Authoritative accepted domain

When to use it. All valid recipients for a namespace are represented in the organization and unknown local addresses should be rejected.

An authoritative domain treats the organization as responsible for recipient resolution in that namespace. Check aliases and synchronized recipient objects before classifying a recipient as nonexistent.

Certificate-authenticated inbound connector

When to use it. A partner relay has changing IPs but presents a trusted TLS certificate with an agreed subject name.

A scoped inbound connector can identify the partner by its TLS certificate name under the configured requirements. After renewal verify the presented certificate, chain, name and connector scope.

Outbound connector smart host

When to use it. Mail for one partner domain must go through an approved external gateway rather than normal MX routing.

A scoped outbound connector can direct matching mail to specified smart hosts and enforce TLS requirements. Validate the connector using a recipient in its scope and inspect routing or TLS failures.

Enhanced Filtering for Connectors

When to use it. Mail reaches Microsoft 365 through a third-party filtering gateway and sender verification sees the gateway hop.

Enhanced filtering accounts for trusted intermediary hops so filtering can evaluate the original source more accurately. Identify the legitimate gateway IPs and apply the setting to the correct inbound connector.

Mail flow rule evaluation

When to use it. Only messages matching a particular sender and recipient combination require an extra transport action.

Transport rules inspect messages in transit and evaluate scoped conditions, exceptions and actions in priority order. Check higher-priority rules and any stop-processing action before assuming the rule was skipped.

On-premises queue inspection

When to use it. Exchange Online accepted an outbound handoff, but a local transport server is retrying delivery to the next hop.

Get-Queue shows queue status and last errors on the on-premises transport service. Use the destination and last error to distinguish DNS, connection and TLS failures.

Hybrid deployment and coexistence

Hybrid Configuration Wizard

When to use it. A replacement transport certificate and a changed hybrid transport server require coordinated hybrid configuration updates.

The wizard applies selected coexistence settings across the on-premises organization and Exchange Online. Review chosen features and preserve intended customizations before rerunning selected configuration steps.

Centralized mail transport

When to use it. An organization requires applicable outbound internet mail from cloud mailboxes to pass through its on-premises mail system.

Centralized routing uses the hybrid transport path to send the relevant cloud outbound mail through on-premises infrastructure. Size the on-premises route for cloud outbound traffic and test behavior during an on-premises outage.

Remote routing address

When to use it. An on-premises mail user representing a cloud mailbox must forward delivery to its tenant routing namespace.

The remote mailbox's target routing address directs on-premises mail to its Exchange Online destination. Inspect RemoteRoutingAddress on the remote object and verify the tenant routing domain is correct.

Hybrid free/busy direction test

When to use it. Cloud users can see cloud calendars, but an on-premises requester cannot retrieve availability for a migrated mailbox.

Testing each direction separately isolates the requesting organization, discovery target and cross-organization authentication path. Use paired test mailboxes and record which direction fails before changing organization relationships.

Autodiscover service connection point

When to use it. Domain-joined Outlook clients inside the network contact a retired server even though public Autodiscover DNS is correct.

On-premises Active Directory can publish Autodiscover service connection point URLs to internal clients. Inspect AutoDiscoverServiceInternalUri on the client access services and check internal DNS resolution.

MRS Proxy

When to use it. A remote move endpoint cannot reach the on-premises mailbox replication proxy on the published EWS virtual directory.

MRS Proxy exposes mailbox replication operations used in hybrid remote moves. Verify MRSProxyEnabled, external publishing, authentication and certificate trust for the selected endpoint.

Migration endpoint test

When to use it. A move batch fails before any mailbox data transfers and all affected users share the same remote endpoint.

Test-MigrationServerAvailability checks connectivity and configuration for the specified migration path. Use settings matching the migration type and investigate endpoint failures before altering individual mailboxes.

Exchange GUID comparison

When to use it. A remote move reports that the target mailbox identity does not match the expected mailbox.

The ExchangeGuid links the mailbox identity used by Exchange during a move. Compare the authoritative on-premises remote object and cloud mailbox before changing a GUID.

Hybrid OAuth validation

When to use it. Free/busy calls reach the correct EWS URL but return authentication errors after certificate maintenance.

Test-OAuthConnectivity can exercise service-to-service authentication for a specified service and mailbox. Check issuer, authentication certificate validity and the correct target URI when interpreting the result.

Organization relationship scope

When to use it. Cross-organization availability works for one address space but fails for another hosted by the same partner.

An organization relationship defines partner domains and permitted availability detail and scope. Inspect DomainNames, FreeBusyAccessEnabled and access level on the requesting side.

Recipients and delegation

Remote shared mailbox conversion

When to use it. A previously migrated user mailbox must become shared while its traditional synchronized remote object remains on-premises authoritative.

The migrated mailbox and its on-premises remote mailbox representation need consistent recipient types. Set the on-premises remote type and cloud mailbox type as applicable, then verify both after synchronization.

Full Access delegation

When to use it. An assistant must open another mailbox and maintain its calendar and folders.

Full Access permits opening and managing mailbox contents through the assigned mailbox permission. Sending as the mailbox requires a separate sending permission.

Send As delegation

When to use it. A shared support address must appear as the sender without exposing a delegate in the From line.

Send As authorizes sending with the represented recipient's identity in the message sender presentation. Check recipient permissions in the correct environment and allow for permission propagation.

Send on Behalf delegation

When to use it. Recipients should see the employee's name acting on behalf of a department mailbox.

GrantSendOnBehalfTo configures delegates whose messages identify the delegate acting for the mailbox. Verify the delegate in the mailbox property rather than inferring it from Full Access.

X500 proxy preservation

When to use it. After a recipient migration, replies to old internal messages fail with an IMCEAEX-style unresolved address.

Adding the prior legacyExchangeDN as an X500 proxy preserves resolution of old Exchange identities. Obtain the original legacy address or accurately decode the NDR before applying the proxy at its authority.

Synchronized distribution group membership

When to use it. A cloud-side change to a traditionally directory-synchronized distribution list is rejected or disappears after sync.

The authoritative on-premises group controls synchronized membership. Make the membership change at the source and check sync status and cloud expansion afterward.

Soft-deleted mailbox lookup

When to use it. A recently deleted cloud user may still have a recoverable mailbox. You need to find its original mailbox identity.

A soft-deleted mailbox query searches mailboxes retained after removal within their recoverable window. Match ExchangeGuid and deletion timing before choosing a supported recovery procedure.

Shared mailbox licensing review

When to use it. A shared mailbox is approaching the unlicensed storage limit and its owner also requests archiving or hold.

Shared mailbox capacity and advanced features depend on the license and feature entitlements assigned. Verify size, archive and hold requirements before removing a user license after conversion.

Calendar processing policy

When to use it. A room mailbox accepts overlapping requests despite the booking policy expected by facilities staff.

Calendar processing settings govern booking automation, conflicts and in-policy request handling. Inspect AutomateProcessing, AllowConflicts and the relevant booking window and delegates.

Hidden address list visibility

When to use it. A valid recipient receives mail at its address but does not appear in the global address list.

Hiding a recipient from address lists controls directory visibility independently of mail delivery. Check HiddenFromAddressListsEnabled at the authoritative source and allow for address book refresh.

Exchange Online PowerShell

Get-ConnectionInformation

When to use it. A child PowerShell process cannot see the Exchange Online connection opened by its parent console.

The cmdlet enumerates REST-based Exchange Online connections in the current PowerShell instance. Inspect the process actually executing Exchange cmdlets and connect there when it runs independently.

Get-EXOMailbox property selection

When to use it. A large mailbox inventory shows empty fields because the default EXO property set omitted requested attributes.

Get-EXOMailbox supports selected properties and property sets to retrieve additional attributes efficiently. Request the needed properties on retrieval before piping output to Select-Object.

Server-side EXO filtering

When to use it. An inventory script is slow because it retrieves all mailboxes before narrowing the type.

Supported recipient type parameters and server-side filters reduce the result set before transmission. Validate supported filterable properties and specify the required result size.

Certificate-based app-only EXO connection

When to use it. A scheduled inventory job must authenticate to Exchange Online without an interactive administrator.

An app registration and certificate can establish an app-only Exchange Online PowerShell connection. Validate Exchange permissions, role scope, certificate validity and private-key availability to the job account.

Exchange Online RBAC inspection

When to use it. An authenticated operator sees fewer Exchange cmdlets or parameters than a colleague in the same tenant.

Exchange management roles expose permitted cmdlets and parameters through role assignments. Check effective role assignments and scope before attributing missing commands to a module installation.

Connect-IPPSSession

When to use it. A messaging administrator has an active EXO connection but needs Security and Compliance PowerShell commands.

A separate compliance PowerShell connection loads supported Purview and security cmdlets for the session. Confirm required compliance roles and the tenant context for the connected account.

Throttling-aware inventory

When to use it. A long read-only inventory intermittently receives transient service throttling responses.

Bounded retries with backoff and resumable checkpoints let the client respect service capacity. Keep stable item identifiers and avoid retrying permanent permission or validation errors.

Defender for Office 365

Safe Links

When to use it. A user clicked a message URL that was harmless at delivery but became malicious later.

Safe Links can evaluate supported URLs at click time according to the policy applying to the recipient. Check click protection settings and the applicable recipient policy.

Safe Attachments

When to use it. A mail security team wants suspicious file attachments evaluated in a detonation environment.

Safe Attachments analyzes attachments for malicious behavior before or during supported delivery workflows. Check the actual recipient policy and delivery action when investigating a delayed attachment.

Preset security policy precedence

When to use it. A user scoped to a Strict preset does not receive the expected custom anti-phishing settings.

For the relevant protection feature, applicable preset settings take precedence over custom policies. Inspect Strict and Standard assignments and exceptions before changing a custom policy's priority.

Quarantine policy

When to use it. Two recipients see different release controls for quarantined messages of different threat types.

Quarantine policy and detection category govern which end-user actions are available. Review the quarantining protection rule, verdict and linked quarantine policy before granting any release action.

User submissions investigation

When to use it. A user reported a legitimate message as phishing and administrators need to review the report and verdict.

The submissions experience records user or admin submissions for analysis and tracking. Review headers, delivery details and analysis results before changing an organization-wide allow policy.

Zero-hour auto purge

When to use it. Mail initially reaches an inbox but later disappears after new threat intelligence identifies it as malicious.

ZAP can act on eligible messages after delivery when the service changes its verdict. Compare original and latest delivery location and post-delivery action history.

Impersonation protection

When to use it. A message uses a lookalike executive identity and the organization wants targeted protection for high-value people.

Anti-phishing policy can protect selected users and domains from impersonation. Inspect protected identities, policy scope and trusted exceptions when evaluating a missed detection.

Purview compliance

Purview retention precedence

When to use it. A mailbox item falls under a delete schedule and a separate longer preservation requirement.

Retention takes precedence over deletion when applicable retention settings conflict. Evaluate every applicable hold and retention setting before predicting final deletion.

Litigation Hold

When to use it. Counsel needs a mailbox preserved despite user deletion during an investigation.

Litigation Hold preserves relevant mailbox content, including deleted or changed items in recoverable storage. Verify licensing, hold status and recoverable storage capacity for the affected mailbox.

eDiscovery case hold

When to use it. A legal team must preserve specified data sources for a particular case and may narrow the scope by query.

A case hold preserves matching content in the selected locations within the eDiscovery workflow. Verify source selection, query conditions and successful application of the hold.

Exchange DLP policy match

When to use it. Outbound email carrying sensitive identifiers should prompt or restrict users according to a compliance rule.

A Purview DLP rule evaluates supported message content and context at the Exchange location. Check location, confidence, instance thresholds and exceptions before changing enforcement.

Mailbox audit investigation

When to use it. An owner asks which delegate performed a recorded mailbox action within the audit retention period.

Purview Audit can return supported mailbox operations with actor, affected mailbox and timestamps. Use the operation and actor fields to distinguish delegate activity from owner or service activity.
