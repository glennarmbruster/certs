Exam domain · 25–30%

Tenant management

Custom domain verification

When to use it. A company wants to assign user UPNs under a new internet domain in Microsoft 365.

A DNS proof record demonstrates control of the domain before the tenant can use it. Verify ownership first and schedule mail-routing record changes separately.

Service health dashboard

When to use it. Multiple departments report an outage and the team needs tenant-relevant Microsoft service incidents.

Service health shows active advisories, incidents, affected services and updates. Compare the incident scope and timestamps with user symptoms before declaring a local fault.

Message center

When to use it. An admin needs advance notice of a planned Microsoft 365 change that may require tenant preparation.

Message center publishes service change notices and rollout communications relevant to the tenant. Record the announced rollout and action dates and assign an owner to follow up.

Usage reports

When to use it. A licensing review requires trends in actual workload adoption across the organization.

Admin center usage reports summarize activity for supported Microsoft 365 services. Check reporting period, refresh lag and privacy settings before attributing usage to people.

Graph PowerShell context

When to use it. A script signed into several organizations and the operator must identify the tenant and scopes used by its current Graph session.

Get-MgContext reports session details including tenant and authentication context. Compare TenantId and Scopes to the intended task before querying directory objects.

Subscribed SKU inventory

When to use it. A licensing script needs service-plan identifiers and available tenant subscription SKUs.

Get-MgSubscribedSku retrieves the organization's subscribed licensing products and included plans. Compare consumed units with applicable prepaid units and inspect service plan IDs.

Group-based licensing errors

When to use it. Employees join a licensed group but some receive a license processing error.

Group-based license assignment processes membership and reports conflicts, prerequisites and location errors. Inspect the affected user's assignment state and usage location before increasing seat counts.

Microsoft 365 group

When to use it. A project needs a common membership backed by a collaboration mailbox and SharePoint site.

A Microsoft 365 group connects shared membership with supported Microsoft 365 collaboration resources. Review group owners and guest membership because access extends to connected resources.

Distribution group

When to use it. A department needs a single email address to expand into recipients without provisioning a collaboration workspace.

A distribution group expands messages to its mail-enabled membership. Check who may send to the group and whether delivery management or moderation applies.

Shared mailbox

When to use it. Several staff need to read and send department mail through one functional address.

A shared mailbox provides a common mailbox delegated to authorized users. Configure Full Access and sending permissions according to each delegate's duties.

Organizational profile

When to use it. The tenant's official contact and organization details need to be updated centrally.

Organization profile settings hold service-level information about the organization. Check which administrative role can edit the particular organization setting.

Least-privileged administrator role

When to use it. A technician needs to reset eligible users' passwords without becoming a global administrator.

Directory roles separate administrative duties and restrict what a role holder may change. Check which target roles the chosen admin role can reset before assigning it.

Microsoft 365 Backup

When to use it. A tenant needs a restore workflow for supported Microsoft 365 content protected under a backup policy.

The backup service creates recovery points for covered workloads and supports restore operations. Confirm policy coverage, workload granularity and restore point availability before an incident.

Exam domain · 25–30%

Entra identity and access

Entra Connect Sync

When to use it. User accounts are sourced in on-premises AD and require a supported synchronization engine with configurable synchronization rules.

Connect Sync imports, synchronizes and exports objects and supported attributes between directories. Review connector errors and pending changes when cloud values diverge from the directory source.

Entra Cloud Sync

When to use it. A company wants lightweight provisioning agents with synchronization configuration managed from the cloud.

Cloud Sync uses cloud-managed configurations and on-premises agents for supported hybrid provisioning scenarios. Compare required topology, attributes and device scenarios with supported Cloud Sync capabilities.

Password hash synchronization

When to use it. The business needs synchronized users to authenticate in the cloud even when the on-premises sign-in infrastructure is offline.

A derived password hash is synchronized so the cloud service can validate credentials. Verify that password sync has successfully processed a changed password before testing cloud sign-in.

Pass-through authentication

When to use it. Policy requires the user's password to be checked against on-premises AD during each supported cloud authentication.

Registered authentication agents securely validate sign-in credentials against domain controllers. Deploy redundant agents and monitor agent health and connectivity.

Conditional Access policy

When to use it. An application should require compliant devices only for selected users outside trusted conditions.

Conditional Access evaluates scoped signals and applies configured grant or session controls. Use report-only evaluation and examine affected sign-ins before enforcement.

Phishing-resistant authentication strength

When to use it. Privileged sign-ins must use a qualifying cryptographic authentication method instead of a weaker MFA method.

An authentication strength limits which method combinations satisfy the policy's grant control. Provision suitable methods for administrators before enforcing the requirement.

Microsoft Entra ID Protection

When to use it. An administrator must investigate a user whose credential risk has accumulated across suspicious events.

Identity Protection exposes user and sign-in risk information and remediation workflows. Determine whether the finding concerns the individual session or persistent user risk.

SSPR with password writeback

When to use it. A remote worker needs to reset a synchronized password in Microsoft 365 and use it on a domain resource.

Password writeback propagates supported cloud password resets into on-premises AD. Check delegated writeback permissions and on-premises password requirements when a reset fails.

Authentication methods registration campaign

When to use it. An organization wants to encourage a scoped population to register Microsoft Authenticator at sign-in.

The registration campaign prompts eligible users to register the targeted authentication method. Check the campaign scope, exclusions and the user's current method registration.

PIM activation

When to use it. A directory role is assigned as eligible and a user cannot perform a privileged task until an incident is approved.

Activation grants time-bound active access under the role's configured requirements. Verify approval, activation duration and token refresh after successful activation.

Cross-tenant access settings

When to use it. A partner has performed MFA in its home tenant and the resource tenant wants to trust the partner's claim.

Inbound cross-tenant trust settings can accept selected authentication or device claims from another tenant. Scope trust to the intended partner and review the resource tenant's own access policies.

Sign-in log analysis

When to use it. An employee gets an access denial and supplies a timestamp and correlation ID.

A sign-in event provides authentication details, application, device signals and Conditional Access evaluation. Match the exact resource and sign-in event before acting on a policy named in a different event.

Synchronization error remediation

When to use it. A cloud export rejects a new synchronized user because a proxy address is already present on a different object.

Uniqueness requirements can block attribute export when two objects claim the same address. Locate both objects, determine the proper owner and correct the authoritative source before retrying sync.

Exam domain · 30–35%

Defender XDR

Defender XDR incident queue

When to use it. The SOC needs a single investigation that connects related endpoint, mailbox and identity alerts.

Defender XDR correlates related alerts and artifacts into incidents with actions and timelines. Assign an owner and review the impacted entities and evidence before closing an incident.

Advanced hunting

When to use it. Analysts need a custom query correlating supported email events with endpoint and identity evidence.

Advanced hunting uses KQL to query Defender telemetry tables available to the tenant. Confirm that the relevant service contributes data and that timestamps line up across tables.

Microsoft Secure Score

When to use it. Tenant leadership wants a prioritized view of recommended security posture improvements across Microsoft 365.

Secure Score tracks supported controls, recommended actions and improvement status. Evaluate each action's applicability and business impact before using points as a prioritization measure.

Defender for Identity sensor health

When to use it. A domain controller shows no identity telemetry after maintenance while other controllers report normally.

Defender for Identity relies on healthy sensors collecting supported directory and authentication signals. Verify the affected sensor's service, connectivity and health alerts before tuning detections.

Defender for Endpoint onboarding

When to use it. A newly deployed workstation is missing from the security team's managed endpoint inventory.

Endpoint onboarding connects a supported device's security sensor to the tenant service. Verify device onboarding and sensor health before troubleshooting device risk or timeline data.

Device isolation

When to use it. A confirmed compromised endpoint must stop normal network communication while retaining the supported Defender management path.

Device isolation restricts network connectivity as a containment action for supported devices. Check platform support and record business impact before applying and later releasing isolation.

Vulnerability management recommendations

When to use it. An endpoint fleet has software exposure and the administrator wants to prioritize remediation by devices and risk.

Defender Vulnerability Management connects discovered software weaknesses with exposure and remediation recommendations. Verify affected software versions and impacted devices before assigning remediation work.

Defender for Cloud Apps discovery

When to use it. The tenant needs a list of SaaS services employees access outside the centrally approved catalog.

Cloud Discovery evaluates connected traffic telemetry to identify cloud application usage and risk. Validate telemetry coverage before treating missing application activity as proof of nonuse.

Conditional Access App Control

When to use it. The organization wants supported browser sessions monitored and download restrictions applied in real time.

Conditional Access App Control routes supported sessions through Defender for Cloud Apps session controls. Check app onboarding, sign-in routing and the matched session policy.

Safe Attachments policy

When to use it. The mail team wants files in supported messages analyzed for malicious behavior before final availability.

Safe Attachments analyzes files using a detonation and reputation workflow governed by policy. Review the applied delivery option and recipient scope when a file is delayed or removed.

Safe Links policy

When to use it. A security team wants supported links checked at the moment an employee clicks them.

Safe Links applies URL protection according to the relevant settings and client or workload support. Review the applied policy and click event when investigating a URL that changed reputation after delivery.

Anti-phishing impersonation settings

When to use it. Attackers imitate the display name or domain of a finance executive and need targeted impersonation defenses.

Protected users and domains help anti-phishing policies detect lookalike senders. Check which recipients the policy covers as well as which identities it protects.

Threat Explorer

When to use it. Investigators need to find messages from a campaign and compare original and latest delivery locations.

Threat Explorer provides email investigation filters, verdicts and supported remediation pivots. Check licensing, role permissions and time range before interpreting an empty result set.

Attack simulation training

When to use it. A security awareness team wants a controlled training campaign to measure how staff respond to simulated phishing.

Attack simulation training delivers governed exercises and learning assignments with outcome reporting. Define the target training group and measure reporting behavior as well as click activity.

Automated investigation and response

When to use it. Multiple alerts require evidence analysis and recommended remediation that an analyst can review.

Automated investigations evaluate entities and propose or perform supported response actions according to configuration. Review pending and completed actions in the Action center to confirm actual remediation.

Defender role scoping

When to use it. A regional responder must investigate assigned device groups without receiving broad tenant-wide response permissions.

Defender RBAC can scope supported security permissions to authorized roles and device groups. Check the active workload permissions model and resource scope when an action is unavailable.

Exam domain · 10–15%

Microsoft Purview

Sensitivity label publishing

When to use it. A newly created confidentiality label is absent from the Office client for a pilot group.

A publishing policy makes the label available to scoped users in supported clients. Verify the policy includes the label and pilot users and allow for propagation.

DLP simulation

When to use it. A proposed data loss rule should be measured against real tenant content before it blocks business activity.

Simulation evaluates matches and produces results for tuning before enforcement. Review false positives, confidence levels and workload scope before turning on restrictive actions.

Sensitive information type

When to use it. A DLP rule needs to recognize a structured business identifier with contextual evidence.

A sensitive information type can combine a primary pattern, supporting evidence and proximity with confidence levels. Test representative positive and negative examples to avoid matching unrelated number strings.

Retention policy precedence

When to use it. A manager expects deletion at three years, but the same item is preserved by a seven-year retention requirement.

Preservation requirements take precedence over deletion while the applicable retention period or hold continues. Check all applicable policies, item labels and holds when explaining why deletion is deferred.

eDiscovery case preservation

When to use it. Legal counsel needs data from selected custodians preserved and searchable within a named matter.

A case associates authorized investigators, searches and holds with the legal investigation. Validate hold application to all relevant data sources before collecting search results.

Purview Audit search

When to use it. Compliance staff need to identify the actor and time associated with a recorded SharePoint file operation.

Audit search retrieves supported workload activity with identifiers for the operation, actor and target. Confirm ingestion latency, permissions and the relevant audit retention window.
