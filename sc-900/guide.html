Security, compliance, and identity concepts

Zero Trust

When to use it. Employees on the corporate network must prove their identity and satisfy device requirements before accessing sensitive apps.

Access decisions explicitly evaluate signals, use least privilege and assume that compromise is possible. Reevaluate access as risk or device posture changes rather than relying on network location alone.

Defense in depth

When to use it. A security architect wants several independent safeguards between an attacker and protected data.

Multiple layers reduce dependence on the effectiveness of any one control. Combine controls at physical, identity, network, compute, application and data layers as appropriate.

Encryption

When to use it. A file must remain confidential at rest but authorized users must recover its original contents.

A cryptographic key transforms plaintext into ciphertext and enables authorized decryption. Protect and manage keys because access to a decryption key can expose the original data.

Hashing

When to use it. A publisher needs customers to check whether a downloaded package matches a trusted digest.

A one-way function produces a fixed-length digest for comparison. Obtain the expected digest through a trusted channel so that a replaced package cannot supply its own reference.

Federation

When to use it. A partner must authenticate its own employees while a separate organization accepts the resulting assertions.

A trust relationship lets one identity provider vouch for a user to a relying party. Validate the issuer and audience before accepting an identity assertion.

Exam domain · 25–30%

Microsoft Entra capabilities

Microsoft Entra tenant

When to use it. A company needs its own instance of the directory containing users, groups and enterprise applications.

A tenant acts as an organization-specific identity and administration boundary. Check the tenant ID when the same sign-in name appears in more than one directory.

Multifactor authentication

When to use it. A password alone must be insufficient to complete an interactive sign-in.

A second verification factor from a different category increases confidence in the user's identity. Two different passwords are both knowledge factors and do not satisfy the factor diversity requirement.

Single sign-on

When to use it. An employee wants to access several trusted applications after authenticating once.

Applications rely on a common identity provider and a sign-in session to avoid repeated credential entry. Each application still enforces its own authorization after the identity has been established.

Conditional Access

When to use it. Finance requires stronger sign-in controls for sensitive apps when users connect from unmanaged devices.

Policies evaluate identities, target resources and conditions to apply access or session controls. Test a scoped policy in report-only mode and examine sign-in results before enforcement.

Self-service password reset

When to use it. Employees should regain access after forgetting a password without contacting the service desk.

Registered verification methods let users prove identity and reset their own password. For on-premises accounts, check password writeback requirements if a cloud reset must update AD.

Microsoft Entra ID Protection

When to use it. An identity team needs to investigate risky users and respond to anomalous sign-ins.

Identity Protection evaluates risk signals and presents risk detections for investigation and policy. Distinguish a risky sign-in event from the accumulated risk attached to a user account.

Privileged Identity Management

When to use it. Administrators should activate a privileged role for a limited period with approval.

Eligible assignments can require activation steps before role permissions become active. Check activation duration and whether an assignment is eligible or already active.

Access reviews

When to use it. A sponsor must periodically attest whether guests still need membership in a sensitive group.

Recurring reviews collect decisions about continued access and can apply removal results. Set reviewers, fallback behavior and actions for nonresponse to match the business policy.

Microsoft Entra External ID B2B collaboration

When to use it. Partner employees need invited guest access to a corporate application using their home credentials.

A guest representation in the resource tenant enables collaboration with externally authenticated people. Review both resource-tenant authorization and cross-tenant access settings.

Managed identities

When to use it. A workload running on an Azure service needs tokens without an administrator managing a client secret.

Azure manages credentials for the workload identity and issues tokens for supported resources. Grant the identity an appropriate role on the target resource after enabling it.

Exam domain · 35–40%

Microsoft security solutions

Network security group

When to use it. A subnet needs basic inbound and outbound filtering by protocol, source, destination and port.

Ordered stateful rules permit or deny packets at network interfaces or subnets. A lower numeric priority wins when multiple rules could match the same traffic.

Azure Firewall

When to use it. A hub network needs centralized managed inspection and network or application filtering across spokes.

Azure Firewall evaluates traffic routed through a managed stateful firewall service. Verify routing actually sends the intended traffic to the firewall for inspection.

Web Application Firewall

When to use it. A public HTTP application needs managed inspection of web requests against common application-layer patterns.

A WAF policy evaluates HTTP traffic at a supported application delivery service. Review detection versus prevention mode when a matched rule is logged but traffic continues.

Azure DDoS Protection

When to use it. An internet-facing workload requires protection against volumetric attacks on its public network endpoints.

The service monitors traffic patterns and mitigates distributed denial-of-service traffic at the network layer. Select the appropriate protection tier and verify that the target public IP is covered.

Azure Bastion

When to use it. Administrators want to open RDP or SSH sessions to virtual machines without assigning each VM a public IP.

Bastion brokers supported management connections over a managed service into a virtual network. Allow required traffic from the Bastion deployment to the target VM.

Azure Key Vault

When to use it. A service needs a centrally controlled location for secrets, keys and certificates.

Key Vault stores protected material and controls data-plane operations with authorized identities. An Azure management-plane role alone need not grant access to read a stored secret.

Defender for Cloud secure score

When to use it. A cloud team needs a prioritized measure of how its resources align to recommended security controls.

Secure score aggregates posture recommendations and their potential contribution to improvement. Inspect unhealthy resources behind a recommendation before planning remediation.

Microsoft Sentinel

When to use it. A SOC wants to ingest logs from Microsoft and non-Microsoft sources and correlate them in one SIEM.

Data connectors and analytics rules bring telemetry together and generate incidents for investigation. Check connector health and data arrival before investigating why an analytics rule is silent.

Defender for Endpoint

When to use it. A SOC analyst needs device timelines and the ability to isolate a compromised workstation.

Endpoint detection and response collects device telemetry and supports device-level response actions. Onboard the device and verify sensor health before expecting a usable timeline.

Defender for Identity

When to use it. A security team needs detections from activity involving on-premises Active Directory domain controllers.

Identity sensors observe supported on-premises identity signals and surface suspicious activity. Check sensor health and directory service configuration when expected signals are absent.

Defender for Office 365

When to use it. A mail security team wants malicious-link and attachment protection for Microsoft 365 email.

Safe Links and Safe Attachments inspect supported URLs and files according to policy. Inspect policy scope and priority when a recipient did not receive the expected protection.

Defender for Cloud Apps

When to use it. Security wants to identify unsanctioned SaaS usage by analyzing organizational traffic logs.

Cloud Discovery identifies cloud apps in traffic data and supports assessing their risk. Check which users, devices or egress points supplied the discovery data.

Defender XDR incidents

When to use it. A SOC needs to view related email, identity and endpoint alerts as one investigation.

Cross-product correlation groups related alerts and evidence into an incident. Review the incident timeline and impacted entities before choosing a response action.

Exam domain · 20–25%

Microsoft compliance solutions

Sensitivity labels

When to use it. Confidential design documents must carry a classification and, where configured, usage protection.

Labels can apply persistent classification, markings and encryption to supported content. Publishing a label makes it available to the scoped audience while protection depends on its configured settings.

Data loss prevention

When to use it. A team wants to warn or block users when supported content containing sensitive identifiers is shared.

DLP policies combine locations, conditions and actions to control sensitive data use. Test the rule with representative content and check matched conditions before enforcement.

Retention policy

When to use it. All mail in selected mailboxes must be kept for a defined period regardless of folder structure.

A location-scoped policy applies retention settings across supported content. Review overlapping preservation requirements before predicting the final deletion date.

Retention label

When to use it. Only final contract documents need item-level retention starting from a business event.

A retention label associates a supported item with its records or lifecycle settings. Configure the trigger and ensure the item receives the intended label.

Microsoft Purview Audit

When to use it. An investigator needs evidence about who performed a recorded file or administrative action.

Audit search retrieves supported activities with information about actors, operations and times. Use an appropriate search window and account for workload-specific ingestion delays.

Microsoft Purview eDiscovery

When to use it. Legal counsel needs a case to preserve and search electronically stored material for litigation.

Case-based workflows scope custodians or sources and collect potentially relevant content. Assign case access and verify the intended locations before relying on search results.

Compliance Manager

When to use it. A compliance lead wants a view of progress against a regulatory assessment and improvement actions.

Assessments organize shared responsibilities, evidence and improvement actions into a compliance score. Treat the score as progress toward controls and obtain appropriate evidence for an audit.

Service Trust Portal

When to use it. A procurement team needs Microsoft audit reports and assurance documentation for a vendor review.

The portal provides service trust documentation and independent assessment materials. Sign in and accept applicable access conditions for protected reports.
